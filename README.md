# openworld · 共建小镇

可运行的多人共建网站第一版。沿用openworld模型与天空系统，包含固定算法生成的自然地形、GitHub OAuth 登录、个人地块领取、GLB 技术校验、人工审核、审核后公开展示、地图分区加载、建筑预览和第一人称散步。

## 本地运行

需要 Node.js 22.13+（已在 22.22 上验证）。

```sh
npm ci
npm run build
npm run dev
```

打开 http://127.0.0.1:8787 先浏览官网介绍、共建指南和更新资讯，点击「进入小镇」到 `/game`。官网不加载三维游戏资源。在游戏中使用 GitHub 登录后可领取地皮、上传模型；管理员由 `ADMIN_GITHUB_IDS` 指定。测试数据写入 `data/`；部署使用全新数据卷，不要把本机开发数据库带上公网。

示例建筑：[樱花咖啡屋 GLB](public/example-building.glb)，约 190 KB、1664 三角面、26×25 米占地、10.05 米高。可直接上传并审核；生成源码在 `scripts/example-building.mjs`。

## GitHub 登录

1. 复制 `.env.example` 为 `.env`。
2. 在 GitHub Settings → Developer settings → OAuth Apps → New OAuth App 创建应用。
3. 本机 Homepage URL 填 `http://127.0.0.1:8787`，Authorization callback URL 填 `http://127.0.0.1:8787/auth/github/callback`。
4. 将 `GITHUB_CLIENT_ID` 和 `GITHUB_CLIENT_SECRET` 填入本机 `.env`。不要写进前端或提交进 Git。
5. `ADMIN_GITHUB_IDS` 填管理员的 **GitHub 数字用户 ID**，多个以逗号分隔；可在 `https://api.github.com/users/你的用户名` 的 `id` 字段查看。
6. `npm start` 使用真实 GitHub OAuth。上线应另建生产 OAuth App，并将 Homepage、回调和 `PUBLIC_URL` 换成同一正式 HTTPS 域名。兼容旧域名时设置 `ALLOWED_ORIGINS`（逗号分隔的完整 HTTPS 来源，不支持通配符）；旧域名登录自动跳转到正式域名，Cookie 保持仅限当前主机，保存操作仍需 CSRF。多人连接使用同一白名单，左上角显示游戏 WebSocket RTT 和断线原因。

认证使用一次性 state、PKCE、服务器端会话、HttpOnly Cookie 和写操作 CSRF 校验。仅查询 GitHub 公开身份，不请求仓库或邮箱权限，不保存 GitHub access token。实际 OAuth 登录需配置后由账号持有人完成；当前测试验证了回调保护与权限流程，未声称已完成真实 GitHub 端到端登录。

## 核心规则

- 每个 GitHub 数字账号 ID 一块地，坐标唯一；当前不能转让或释放。
- 地块 64×64 米、建筑高 600 米。地块编号只作为地址，实际中心、边界、入口和海拔由服务器规划记录决定，不再用编号乘固定间距摆放。
- 城市规划 v1 使用固定种子 734921。全局道路轴线与河流规则决定交通走廊和桥位，约 560 米的区域包含 2×2 街区；区域内部沿道路配置地块、护岸、绿地和小广场。相邻区域共享同一道路 ID 和边界几何，区域之间无独立随机接口。
- 进入新位置自动计算当前规划区域及外围一圈（3×3 区域），开放前校验道路连通、入口位置与坡度、地块重叠及区域边界。规划 JSON、版本和地块高度保存至 SQLite 的 city_regions；重复访问或重启读取保存结果，不再次生成。
- 先整平街区再切地皮。普通城市地面坡度按不超过 3% 设计，地块与周边整平前高差不超过 1 米；道路和地块入口校验 5% 纵坡上限。河床局部下切，河流周边留公共护岸，不分配地皮；桥面使用连续道路高度，可步行过河。
- 本次接入保留已有领地的实际中心、海拔、主人和发布建筑。city_legacy 冻结旧地基，新地块避让，道路局部绕行。旧的高地基仍可能有明显高台边缘，这属于保留历史场地，并不套用新城区坡度目标。
- 规划算法在 shared/city-plan.mjs，旧 shared/terrain.mjs 保留历史迁移与回归函数。city-terrain 版本不匹配会拒绝静默升级；修改全局地形/道路接口需要版本兼容实现或专门迁移，不能直接更改已有区域。保留的旧布局 v1→v2 迁移只服务历史数据库，不是此次城市接入时的地基重算。
- 世界随探索按需延展，计算区域与领地互相独立。前端使用局部坐标，复用/释放地形网格，在外围数据内提前切换新区；无需玩家点击扩张按钮。探索坐标仍有 floor(2^40 / 70) - 32 的浮点精度保护，已探索规划占用持久存储，不代表数学意义的无限容量。
- 同时显示最近的最多 16 栋玩家建筑，其他建筑靠近后加载；网站每 15 秒同步当前区域。全部审核通过的建筑都持久保存在公共世界，访客无需登录即可查看。
- 每人最多 1 份待审核提交、20 个历史版本；每小时 8 次上传尝试。更新待审或退回时，旧版建筑仍保持公开，批准新版时原子替换。
- GLB 最大 12 MiB，10 万三角面、200 绘制单元、512 节点。所有贴图内嵌，单张最大 2048×2048。详细规范见 `public/BUILDING_SPEC.md`。
- 独立 Worker 校验 GLB，禁止外链、扩展、动画、骨骼、形变、非三角形网格；根据实际变换后顶点计算尺寸，不信任前端尺寸或文件名。最多同时校验 2 份模型。
- 待审核、退回和历史模型只允许作者及管理员获取；仅当前已发布模型对外公开。
- 管理员在工作台旋转预览后批准或退回，审核人、时间和备注入库。第一版没有已发布建筑下架界面，正式社区运营前应补齐投诉/下架流程。

## 游览与创作

### 同一个公共世界

玩家通过 `/realtime` WebSocket 加入同一个服务实例维护的公共世界。登录玩家的名字和角色模型由服务端会话确定，访客获得临时名字。同步位置、朝向、行走/奔跑/坐下和驾驶姿态；其他玩家头顶显示名字，模型支持已上传的绑骨 GLB。上帝视角只观察，不把空中相机显示成人物。

状态每秒同步 10 次，按空间分区向每人发送 180 米内最近的最多 16 名玩家，客户端平滑插值并限制同时加载模型数量。断线自动重连，离开玩家会移除；同一账号同时打开多个页面时仅最新连接展示角色。反向代理需要支持 WebSocket Upgrade，部署保持单副本。

此阶段是玩家实时可见功能：移动与碰撞仍由各自客户端计算，玩家之间暂不碰撞。驾驶时能看到对方的载具，但载具仍是个人实例，尚未实现公共载具抢占、载客、服务器物理判定或反作弊。高频位置不写入 PostgreSQL；数据库继续保存领地、账号和模型。

登录玩家的最后游玩位置每 5 秒保存到数据库，断开连接及服务正常停止时补存；再次进入时按账号恢复。访客位置每 2 秒保存在当前浏览器，关闭页面时补存。上帝视角不覆盖最后游玩位置，短暂网络重连不强制传送；重新进入时以步行状态落在原位置或附近可站立的地面。位置记录按世界种子和版本隔离。断电或进程崩溃可能退回到最近一次定期保存的位置。

点击「河水互动」定位附近河流，再点击水面施加扰动。水面采用局部 65×65 浅水波动网格，按水深传播、岸边无通量反射及阻尼衰减；波高同时驱动网格位移、法线和漂浮物的弹簧浮力/阻尼。反射纹理为 256×256、最多每秒更新 8 次，波纹仍随画面持续更新；自然河流与示范小镇河面都使用动态材质。

这是固定河床上的局部水面物理，不是完整三维流体或洪水模拟。波浪在每个访客浏览器本地计算，跨出局部模拟区会重置，不在玩家之间同步，也不会改变地形、冲走建筑或提供游泳玩法。漂浮物用于展示水面起伏与水流漂移。

拖动旋转、滚轮缩放、右键平移；也可通过 X/Z 导航定位附近，点击实际沿街地块领取。选择「第一人称散步」后 WASD 移动、Shift 奔跑、空格跳跃，鼠标转向；Esc 释放鼠标，点击画面继续。支持 Pointer Lock 的浏览器可连续转向，否则使用画面内鼠标移动。第一版在线散步针对桌面键鼠，手机可使用地图和提交页面。

玩家建筑使用整体包围盒碰撞；散步跟随街区、道路和桥面高度，并阻止直接走入河道或爬上陡坡。公共示范区为视觉场景，未迁移原离线小镇的逐物件导航。当前未实现聊天、AI NPC、经济交易或网站内直接调用 Codex。创作者在自己的 Codex 中完成建模，再上传 GLB。

## 部署

个人载具：按 `P` 在附近安全位置召唤/收回一辆个人小汽车，`F` 上下车；下线强制收回，模型保留。游戏账号面板可上传 GLB，也可执行 `node cli/openworld.mjs vehicle set car.glb`。模型宽 ≤1.9 m、高 0.5–2 m、长 ≤4.1 m，≤12 MiB，沿用小汽车手感、碰撞和座位。独立车轮节点 `wheel_fl/fr/rl/rr` 支持滚动与转向；详细约定见建模 skill。载具模型通过技术校验后直接替换账号模型，不进入建筑审核。其他玩家可以看到停放和驾驶中的个人汽车，但不能驾驶别人的车。

审核后台位于 `/admin`，管理员也可从游戏账号面板的「审核工作台」进入。未登录会跳转 GitHub，登录后返回后台；服务端按 `ADMIN_GITHUB_IDS` 中的固定 GitHub ID 授权，线上 `tamikip` 对应 `147692760`。后台支持待审核、已通过、已退回及历史版本分页列表，旋转/缩放 GLB 预览、通过公开与填写原因退回。模型预览成功后才允许审核；每次审核记录审核人、时间和备注。

生产环境采用 **单实例 Node + PostgreSQL + 持久文件存储**。用户、会话、领地、审核记录和世界规划存入 PostgreSQL；上传的 GLB 保存在 `/app/data/uploads`。本地未配置 `DATABASE_URL` 时仍可读取原 SQLite 开发世界，不会自动迁移或删除旧数据。不可直接部署到 GitHub Pages。

### Docker / VPS

设置 `.env` 中的 `PUBLIC_URL=https://你的域名`、OAuth 配置、管理员 ID 和强随机 `POSTGRES_PASSWORD`（使用 URL 安全字符），执行：

```sh
docker compose up -d --build
```

Compose 启动 PostgreSQL 18，等待健康检查通过后启动应用；数据库端口不暴露到宿主公网。应用仅将 8787 暴露给宿主本机，使用 Caddy（见 `Caddyfile.example`）或已有反向代理提供 HTTPS。数据库和上传模型使用两个独立持久卷。生产配置不完整时服务会拒绝启动。

### 支持 Docker 的托管平台

Zeabur 在同一项目中创建 PostgreSQL 服务，将应用的 `DATABASE_URL` 设置为平台共享变量 `${POSTGRES_CONNECTION_STRING}`。应用监听 `PORT`（默认 8787），公网端口须一致；上传模型持久卷挂载 `/app/data`，并保持 **单副本**。数据库无需开放公网。首次启动自动创建表，重启保留数据；`/health` 会实际查询数据库。

备份时暂停应用写入，使用 `pg_dump` 备份数据库并同步备份上传模型卷；恢复时使用同一时间点的两份备份。不要把本地 SQLite 测试数据复制到线上，也不要对在线 PostgreSQL 数据目录做普通文件复制。未来扩容多个应用副本前，需要将模型迁到共享对象存储并处理进程内缓存。

PostgreSQL 集成测试使用专用测试数据库连接 `TEST_DATABASE_URL`，执行 `node --test test/postgres.test.mjs`。测试只创建并清理随机命名的独立 schema，覆盖并发领取、事务回滚、审核、CLI 授权、上传与重启持久化；不要使用生产数据库运行测试。

## 验证与源码

```sh
npm test
npm run build
```

`server/`：数据库、OAuth、API、模型校验；`src/`：地图、建筑工作台与天空；`public/`：页面、模型与规范；`test/`：地块、审核、权限与模型限制的自动测试。

Three.js、Express、glTF Transform、glTF Validator、Sharp 等第三方依赖按其各自许可分发；npm 安装目录保留相应许可信息。
