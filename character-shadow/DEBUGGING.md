## 一、接完的验收标准（4 条，全都要过）

| # | 怎么查 | 期望 |
| --- | --- | --- |
| 1 | 跑 `selfcheck/` | `合计 43 通过 / 0 失败` |
| 2 | `adapter.stats()` | `attached=true`、`skipped={}`、`injected` 随流式加载单调增长不重复 |

## 二、夜间街灯那一项：怎么肉眼验

这一条没法用自动读数在真实场景里验（那些读数需要一个能逐帧 A/B 的环境，
见 [VERIFICATION.md](VERIFICATION.md)），所以把「看什么」写清楚。

**为什么偏偏是夜里**：街灯的强度乘了夜晚因子，白天那个因子是 0、灯全灭 ——
**白天结构性地测不出这个问题**。夜里街灯又正好是画面上唯一的强直射光。

**怎么看**：

1. 把时间调到夜里（夜晚因子 ≈ 1）。
2. 走到一盏**亮着的街灯下面**（灯下那块地是最亮的地方）。
3. 转动视角，让镜头**斜着看角色脚下的地面**（掠射角最容易看出压暗）。
4. 看角色周围那一圈地面，和**几米外没有被角色遮挡的地面**比亮度。

**合格**：角色周围的地面亮度和几米外基本一致 —— 只有一块**很淡的**、月光造成的影子。

**不合格**：角色脚下一圈**边界模糊但明显更暗**的区域，而画面里**找不到任何影子
能解释它**（周围建筑、灯杆都没往那儿投影）。这就是「无光之影」，
说明乘子又在乘点光了。参考量级：出问题的那一版，深核里只剩 28% 的光。

**出问题怎么回退**：`adapter.visible = false`。

要说清楚它的确切语义，免得误判：它**不会**卸掉已经注入的着色器，只是
**不再把角色画进那张图**（每次 `update()` 把图清成「全远」）。图全远 ⇒
`cs` 处处为 1 ⇒ 乘子变成恒等变换 ⇒ **画面回到接入前的原状**。
同时它也**省掉了那趟额外的 `renderer.render()`**（清图那几步还在）。

所以它是个很干净的判据：

- 设成 `false` 暗斑**消失** ⇒ 确认是这个模块造成的，继续往下查；
- 设成 `false` 暗斑**还在** ⇒ 跟这个模块无关，去查别处。

**要彻底关掉**（连注入一起去掉）才需要 `dispose()` + 重建材质。

## 三、症状 → 原因对照表

| 症状 | 最可能的原因 | 怎么确认 |
| --- | --- | --- |
| **某类地面上永远没有角色影子**，且不报错 | 那类材质没进注入（自定义 `ShaderMaterial`、用了 `onBeforeCompile` 的材质等） | `adapter.stats().skipped` —— 它**按材质类型记数**而不是静默跳过，就是为这个。看到的键名就是漏掉的类型 |
| **整片地面黑掉**（不是角色影子，是全黑） | 构造期那次「清成全远」没生效，图里是未定义内容（实测读全 0）⇒ `z-bias <= stored` 基本不成立 ⇒ 全判定在阴影里 | 角色加载完（`attached=true`）之后还是黑的 ⇒ 是这条；加载完就正常 ⇒ 是正常的「加载窗口」，见 INTEGRATION 坑 3 |
| **影子停在某一刻不动了** | 换了模型/皮肤时**重建了 `CharacterShadow`**。已注入材质的 uniform 编译期绑在旧 `rt.depthTexture` 上 | 换模型后立刻出现。查代码里有没有自己 `new` —— 应该走 `attachCharacter()` 换引用 |
| **角色跳出一格 / 整张图变白** | 角色被 move 进了包装组，浮动原点的坐标偏移被改掉了 | 查有没有 `group.add(avatarRoot)` 之类的操作 |
| **主相机看不见角色了** | 图层用了 `layers.set(2)`（替换）而不是 `layers.enable(2)`（并集） | `avatarRoot.layers.mask` 应该是 `5`（= 1\|1<<2），不是 `4` |
| **影子出现两层**（一粗一细） | 角色的 `castShadow` 没关，场景图和专用图都在画 | `attachCharacter()` 会关；若在它之后又被打开，就是这个 |
| **`injected` 每帧暴涨** | `markWorldDirty()` 被挂到了每帧都跑的地方 | 它应该只挂在区块流式的回调里。`injected` 是累计值，每帧重注入会让它线性上涨 |
| **`injected` 卡住不涨** | `markWorldDirty()` 没挂上，或挂了但 `update()` 没在跑 | 先确认 `stats().updates` 在涨，再确认那个回调有没有真的被调用 |
| **VR 里没影子** | 预期行为 —— `renderer.xr.isPresenting` 时 `update()` 直接跳过 | 不是 bug。多跑一趟 `renderer.render()` 会打乱 XR 的 framebuffer 绑定。**但这条要在真机 VR 上确认过才算数** |
| **影子比周围的糊一截 / 锐一截** | `radius` 和场景阴影方案的半影没对齐 | 按 `radius ≈ 场景半影 / 1.56cm` 算（见 INTEGRATION 第四节）。偏大偏小都能一眼看出来 |
| **影子方向不对 / 和太阳不匹配** | 灯的 `target` 被赋了值，或手工调过 `setSunDirection()` | 别手工设方向，让它每帧反推（INTEGRATION 第二节）。`stats().sunDirection` 可以直接和灯的 `position` 反推值对一下 |
| **夜里角色脚下一圈暗斑** | 乘子乘到了点光（本版已修）；或宿主自己加了点光/聚光后又踩到同一处 | 见第二节。`adapter.visible = false` 一关就没 ⇒ 确认是它 |
| **控制台出现「`lights_fragment_begin` 的形状与 r180 不一致」** | **three 的版本变了**（升到了 r181+，或被人 patch 过）。注入靠替换那段 chunk 的文本，形状一变注入点就失配 | 这不是运行期故障，是**版本信号**。模块会**放弃注入**（角色影子不出现，其余一切照常），并只报这一次。照这条信息改 `CharacterShadow.js` 顶部的 `CHUNK_DIR_OPEN` / `CHUNK_RECT_OPEN` 即可。**别忽略它** —— 它专门设计成"宁可不画，也不编译失败" |
| **角色影子边缘缺一块**（尤其放大过的角色、坐骑、角色下挂了别的物件） | 正交盒罩不住投射体，超出盒的部分被**默默裁掉** —— 不报错、不抛异常 | 控制台会有一条一次性的 `[CharacterShadow] 角色包围球半径 … 超过正交盒半边长 …`，按它给的建议值调大 `extent`；同时确认角色下有没有挂着本不该算进来的大物件 |

## 四、还没验证过的（**别当成已经解决了**）

### 1. 性能 —— 没有真机数据

专用图**每帧多一趟 `renderer.render()`**，它只画角色那棵子树（不遍历整个场景，
见下），但仍会重置 `renderer.info`、切换 render target 再切回来。
开发测试台那台机器上的读数**不能外推**，因为场景规模、Draw call 数、GPU 都不是一回事。

**这一趟具体花在哪**（看清楚再测）：遍历只有角色子树那么大（O(角色)，
与场景规模无关），固定开销来自 render target 切换和 `renderer.info` 重置。
所以**关注点不是平均帧率，是那趟额外渲染的固定开销** —— 它和角色复杂度成正比，
和场景规模基本无关。

**已知的优化方向**（都没做）：专用图隔帧刷新、角色没动时不重画（需要位移检测）、
只在角色进入镜头时才画。

### 2. 多人 —— 方案未定

现在只有**本地角色**在图层 2。N 个玩家要各画一张图、着色器里采 N 个 sampler
（sampler 数量有限，且每个都要注入一次），还是**按距离只画最近的一个** ——
这个取舍需要真机性能数据才能定，现在没有结论。

多人还有一个没碰的问题：**别人的角色要不要有高精度影子**。如果只画最近的一个，
远处玩家的影子会在某个距离上突然从「细」跳到「粗」，这个跳变能不能接受也没验过。

### 3. 多 pass 合成器渲染路径 —— 没在真机上验过

朴素 `renderer.render()` 那条路已验证。某些画风会走多 pass 合成器，
`update()` 挂在它最前面就绕开了 read/write buffer 互相喂的问题，
**但这条路径没有在真机上跑过**。挂错位置的症状是画面闪烁或全黑。

### 4. VR —— 见症状表

`update()` 在 XR 呈现中直接跳过，代价是 VR 里角色没影子。
这是「没有」不是「错位」，但**要在真机 VR 上确认过才能算数**。

### 5. 材质换法的两个边角 —— 判据照抄了 three，但没有对应形状的样本

`update()` 为了只画角色子树，改成**手工**把角色的材质临时换成深度材质
（不再用 `scene.overrideMaterial` —— 那个只有传 `Scene` 才生效，就意味着每帧
遍历整棵场景树）。换的判据是照抄 three `renderObjects` 里的那两条：
`allowOverride === true` 才换、`visible` 为假的**根本不该换**（它原本连渲染列表
都进不去，换了等于凭空画回来）。

自检 §11 用「两条路渲出来的图**逐像素相同**」钉住了两个形状：`SkinnedMesh`
（骨骼摆到远离绑定姿势处，蒙皮一失效就会露馅）和 `InstancedMesh`。但这两个
**还没有样本**，所以没验：

- **一个网格挂多份材质**（`geometry.groups` 多分组）：代码是**按槽位**换的，
  理论上等价于 override 的逐组语义；自检里没有这种形状的样本
- **`allowOverride = false` 的材质**：按判据它**不该被换**。自检里也没有这种样本

两条的症状都不会报错，只会「影子的形状不对」。真机上出现对应形状时要单独看一眼。

### 6. 其他没做的

- 角色上下坡/上台阶时专用盒的高度自适应跟随
- 阴影盒边缘淡出（角色走到 4 m 盒边上时影子会被切掉）
- 质量档位：低配机型想降负载时注意 `extent/size` 决定精度，
  降 `size` 会让影子**变糊**，不是简单地变快

## 五、怎么把问题报回来

带上这四样，基本能直接定位：

1. `adapter.stats()` 的完整 JSON（尤其是 `skipped`、`injected`、`updates`）
2. `adapter.probe().count`
3. 出问题时的截图（**注明时间和天气** —— 夜间/黄昏/白天是三个不同的代码路径）
4. 自检页的输出（有 FAIL 的话）

第 1、2 条是关键：**这个模块的故障模式基本都是「静默的」**——
不抛异常，只是「某片地没有影子」。所以那两个读数比截图有用得多。
